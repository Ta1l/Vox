# Review scope

Focus on correctness, security, and invariant preservation in the newly implemented features.

# Focus areas

## 1. API endpoint security

Check:
- Authentication required on all endpoints
- User context validated
- User ownership checked before returning data
- No cross-user data leakage
- Rate limiting present where applicable
- CSRF protection via framework (server actions)

## 2. Input validation completeness

Check:
- All mutation endpoints validate with Zod
- Amount bounds checked (positive, max limits)
- Date ranges validated
- Enum values validated against allowed set
- Foreign key references validated (entity exists and belongs to user)
- String sanitization (transaction descriptions, notes)

## 3. Transaction isolation correctness

Check:
- Multi-table updates in transactions
- Appropriate isolation level (REPEATABLE READ where needed)
- No lost updates in concurrent scenarios
- Audit log entries in same transaction as mutation
- Version fields used for optimistic locking where needed

## 4. Background job idempotency

Check:
- Occurrence generation uses unique constraints
- Job handlers can be safely retried
- Duplicate detection via idempotency keys
- ON CONFLICT DO NOTHING or similar for deduplication

## 5. Financial invariants

Check:
- Debt payments reduce debt balance atomically
- Goal contributions increase saved amount correctly
- Envelope allocations don't exceed available balance
- HARD protection enforced (envelopes + upcoming obligations)
- Protected balance calculation includes horizon obligations
- Discretionary balance = available - protected

## 6. State machines

Check:
- Income status transitions follow documented flow
- Payment occurrence status transitions valid
- Planning cycle status transitions enforced
- No invalid state combinations (e.g., RECEIVED without received_at)

## 7. Date/time handling

Check:
- Timestamps use timestamptz (timezone-aware)
- Date-only fields (due_date) stay as date type
- Recurrence generation handles month-end correctly
- DST transitions considered
- Timezone explicit in queries (AT TIME ZONE 'Europe/Moscow')

## 8. Audit trail

Check:
- Financial mutations logged to audit_log
- Previous state captured
- New state captured
- Metadata includes relevant context
- Audit log append-only (no UPDATE/DELETE permissions)

## Debt payment atomicity

```typescript
// Should be in transaction:
await db.transaction(async (tx) => {
  const debt = await tx.query.debts.findFirst(...);
  const newBalance = debt.currentBalanceKopecks - amount;

  await tx.update(debts).set({
    currentBalanceKopecks: newBalance,
    version: debt.version + 1,
  }).where(and(
    eq(debts.id, debtId),
    eq(debts.version, debt.version) // optimistic lock
  ));

  await tx.insert(debtPayments).values({
    debtId,
    amount,
    previousBalance: debt.currentBalanceKopecks,
    newBalance,
    expenseId: expenseEntry.id,
  });
});
```
